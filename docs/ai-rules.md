# AI Rules — Fluency Studio

---

# Core Rule

DO NOT rewrite the entire project.

All updates must be:
- incremental
- modular
- reversible
- architecture-aware

---

# Architecture Protection Rules

## DO NOT
- Flatten folder structures
- Convert modular systems into monolithic files
- Remove existing systems without approval
- Rewrite unrelated systems during focused updates
- Replace immersive UI with generic UI
- Remove mobile support
- Remove kids-mode support
- Remove resonance-based concepts
- Simplify the project vision

---

# ALWAYS

## Preserve
- immersive visual identity
- futuristic atmosphere
- emotional tone
- mobile landscape compatibility
- touch interaction behavior
- responsive layouts
- existing feature continuity

## Maintain
- modular scalability
- organized structure
- readable architecture
- future extensibility

---

# Update Safety Rules

When implementing updates:

## ONLY modify:
- systems directly related to the requested task

## DO NOT touch:
- unrelated rendering systems
- unrelated UI systems
- unrelated interaction systems

unless explicitly instructed.

---

docs/

---

# AI Workflow Rules

Before implementing updates:
1. Read all docs files
2. Analyze current architecture
3. Preserve continuity
4. Avoid destructive rewrites
5. Prioritize stability

---

# Replit Update Rules

When generating updates in Replit:

## ALWAYS
- preserve imports
- preserve existing systems
- create new modules carefully
- maintain compatibility
- avoid replacing entire files unnecessarily

## NEVER
- regenerate the whole app
- overwrite major systems blindly
- delete folders without confirmation
- replace stable systems with experimental rewrites

---

# Mobile Rules

Mobile experience is a priority.

Maintain:
- landscape compatibility
- touch responsiveness
- immersive fullscreen behavior
- readable controls
- smooth performance

---

# Visual Identity Rules

The project aesthetic must remain:
- immersive
- cinematic
- atmospheric
- emotionally intelligent
- futuristic
- fluid

Avoid:
- sterile enterprise styling
- generic dashboards
- overly clinical presentation

---

# Performance Rules

Prioritize:
- smooth rendering
- stable frame rate
- lightweight interaction systems
- scalable visual systems

Avoid:
- unnecessary heavy calculations
- uncontrolled particle spawning
- excessive DOM manipulation

---

# Documentation Rules

After major updates:
- update roadmap.md
- update current-state.md
- preserve project continuity notes

The docs folder is the persistent project memory system.
